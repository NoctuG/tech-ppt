# 素材流水线：先锁风格，再批量生图

为页面实际调用生图模型制作足量素材，是tech-ppt的核心能力。原生文字不意味着省略图片生产，整页图盖文字框也不能冒充可编辑课件。教材已有原图保留，生成图补充确需的新情境、主体、动作、状态与材质。

## 一、固定顺序与受控回退

教学底稿与拆页 → 风格锁定G1 → 逐页素材清单 → 实际批量生图并验收G2 → 整册组装 → 点击节奏 → 成品检查。

G1前允许生成少量风格候选、试排封面与代表内页；这是样张试制，不是整册组装，不要求先产出全套素材。样张通过后才批量生产。不能一边组装整册一边临时决定画风，也不能先生成全套整页图再企图恢复图层。

若组装发现缺项：暂停受影响页面 → 回写计划与清单 → 按已锁风格补生并验收 → 更新G2记录 → 再组装。固定顺序不禁止受控补图。用户已授权的工作自主推进，不为内部验收逐页索要审批。

## 二、G1风格锁定

style-spec写出具体造型/媒介/笔触、色值与语义、可用字体与字级、阅读区与元件语言、角色身份（没有则写无复现角色）、底图策略、本项目禁止项（没有则写无额外禁止项）。不为填字段虚构偏好。

用两张实际样张验收：封面验证画法、色彩、标题；代表内页带真实材料、任务和所需作答/反馈结构，验证正文可读、材料尺度、背景退让、组件与插画关系。反馈不提前放在首屏。只有漂亮封面不算通过。

可编辑模式优先看原生样张实际渲染；只有生图效果稿时标记效果稿，不当作PPT渲染。无渲染能力时写明未通过视觉验证。用户已选风格可沿用其决定，但仍检验本次真实内容内页。

两页通过后登记style_version与锚点，后续批次引用同一风格。艺术参考约束画法，本项目角色参考才约束身份，不带入旧课题或具体构图。

## 三、逐页需求与素材清单

给每页列visual_slots：职责、关联材料、对象/状态/视角、是否独立移动、来源与asset_id。纯材料页无需额外插画时说明原因，不强加人物。

素材逐项记id、source（generated/textbook/provided/native）、role、pages、style_version、edit_scope、aspect、透明需求、实际提示词位置、实际工具/已知模型、调用或输出标识、文件与验收状态。复现角色另记identity和pose，不能只改文件名当作新姿态。

**足量按真实需求覆盖，不按页数凑独立图片：**

- 必要槽位覆盖率须100%；无槽位的页写无图理由。
- 必需生成项完成率须100%，每项有实际合格文件。不能把所需生图静默改成native或待补。
- 需要几种动作、场景或视角就制作几种；固定立绘可共享，不能代替不同的教学动作。背景可共享，学习主体必须匹配页意。
- 分别报告规划生成项、实际调用、候选、合格项、实际使用和复用页数。复制文件、裁切派生、教材原图和原生组件不算新的生图成果。
- 常规成套课件须实际生产清单中的新素材，不能用一张通用底图忽略其余页需求。用户明确只用已有素材时记录该要求，不虚报生图。

例如12页需要1张共享底图、4种角色动作、2个场景、3个物件，共10项生成素材；另有2张教材原图和1个原生关系图。10项生成全部合格、槽位均匹配即可组装，不为达到12张再造无用图片；某页缺动作，即使已有30张也不通过。

## 四、批量生图

1. 先锚点后批量，按场景、人物或对象成批生产；同批共享风格段，每项单独写主体、动作、视角、留白与输出要求。
2. 使用当前可用且获准的生图工具，用户指定优先。真实调用带必要参考与提示词，不假称工具已读整个聊天；分享技能不含私人路径或凭据。
3. 关键难项先做候选再扩展，合格无需强制多次重生。废弃候选另记，不充当交付素材。
4. 每批看实际图片，画法漂移回到当前锚点纠正。同一问题两次定向修正仍失败则改素材或布局，不无限重试。
5. 参数与并发按实际工具能力；只记录实际使用且已知的模型，不猜引擎，不写永久免费或固定价格承诺。

## 五、逐项验收

| 检查项 | 要求 |
|---|---|
| 任务适配 | 对象、动作、数量、视角与visual_slot一致，无凑数素材 |
| 主体完整 | 独立主体通常留8%—12%安全空间，头手道具完整；背景按构图处理 |
| 身份/画法 | 同角色跨动作身份一致，线条、上色、材质与锚点一致 |
| 编辑边界 | 可移动主体未粘进背景；精确图解、文字、答案、刻度、公式、数据、标签用原生对象 |
| 透明 | 检查实际alpha与深浅底边缘；无可靠抠图时改同底色块并说明 |
| 文件与夹带 | 可访问、可解码、尺寸足够；独立素材无文字、品牌、水印、假透明棋盘格 |
| 来源与记录 | 教材原图有出处；生成项有真实提示词、工具调用/输出记录与合格文件 |

## 六、G2组装前验收

G1仍有效；必要槽位覆盖100%；必需生成项完成100%；各项已验收且有文件；独立动作/场景/物件齐备；透明与风格检查完成。提示词、失效URL、空文件和稍后补图不能通过。

可选运行`scripts/check_asset_gate.py project.json --report gate-report.json`检查文件、引用与覆盖。脚本不证明实际模型调用、视觉质量或教学准确性，仍须看真实记录与图片。

可选JSON结构，路径相对project.json；其他宿主可用等价表格，不要求统一格式：

```json
{
  "style_version": "v1",
  "style_spec": "style-spec.md",
  "anchors": [
    {"role": "cover", "file": "previews/cover.png", "reviewed": true},
    {"role": "inner", "file": "previews/inner.png", "reviewed": true}
  ],
  "required_generated_ids": ["scene"],
  "assets": [
    {"id": "scene", "source": "generated", "file": "assets/scene.png", "accepted": true,
     "style_version": "v1", "prompt_file": "prompts/scene.txt", "tool": "实际工具", "generation_id": "实际输出标识"}
  ],
  "pages": [{"id": "p1", "visual_slots": [{"role": "scene", "asset_id": "scene"}]}]
}
```

source=native的原生对象无需图片文件，但须登记role。reviewed/accepted记录实际检查结果，不可预填。只用已有素材的明确用户要求用existing_only_authorization记录；没有该要求不可据此跳过生图。

## 七、能力不足时

| 情况 | 交付与限制 |
|---|---|
| 无生图 | 完成文案、计划、风格、清单与提示词，明确素材未生成；可用用户已有素材继续，但不称完整生图流程已完成 |
| 无透明/参考输入 | 采用可靠同底色块或文字风格/身份说明，交代限制，不假称已输入参考 |
| 无演示文稿能力 | 素材、文案与组装计划，明确PPT未生成 |
| 无渲染/原生动画能力 | 说明对应验收未完成，不用视频、GIF或另生整图冒充 |

分别列出实际完成与缺失，不静默改变输出模式掩盖缺项。
