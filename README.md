# tech-ppt

面向技术演示文稿（Technical PPT）的技能仓库。仓库用于沉淀可复用的演示文稿制作方法、内容模板和交付规范，帮助团队以一致的结构完成技术方案、产品介绍和项目汇报。

## 当前状态

当前仓库处于初始化阶段，已建立基础文档入口，后续技能内容将按主题逐步补充。

```text
tech-ppt/
├── README.md       # 仓库说明、目录索引与协作约定
├── LICENSE         # 开源许可
└── skills/         # 技能目录（待补充）
    ├── content/    # 内容策划：受众、叙事、页面结构
    ├── design/     # 视觉设计：版式、配色、字体、图表
    ├── delivery/   # 交付制作：演讲稿、演示节奏、检查清单
    └── templates/  # 可复用模板、示例和素材规范
```

## 技能组织方式

每项技能建议独立放在 `skills/` 下的主题目录中，并保持统一结构：

```text
skills/<category>/<skill-name>/
├── README.md       # 技能目标、适用场景与使用方法
├── examples/       # 示例内容或案例
├── templates/      # 可复制的模板文件
└── checklist.md    # 执行与验收清单（可选）
```

技能文档至少应说明：

1. **解决的问题**：技能适用的任务和目标读者。
2. **输入与输出**：开始前需要哪些信息，最终产出什么。
3. **执行步骤**：从内容准备到最终检查的可操作流程。
4. **质量标准**：如何判断产出完整、清晰且可交付。
5. **示例与限制**：推荐用法、反例和已知边界。

## 推荐工作流

1. 明确汇报目标、受众和使用场景。
2. 先搭建信息结构，再确定页面数量和叙事顺序。
3. 使用统一的版式、字体层级和颜色系统。
4. 用图表、流程图或示意图表达关系，减少大段文字。
5. 按交付清单检查事实、数据、可读性和演讲节奏。

## 命名与协作约定

- 目录和文件名使用小写英文与连字符，例如 `system-architecture`。
- 每项新增技能都应包含自己的 `README.md`，并在本文件的目录索引中登记。
- 示例数据应使用脱敏或虚构内容，不提交密钥、客户资料或内部机密。
- 修改前后保持 Markdown 可读性，并在提交说明中写明影响范围。
